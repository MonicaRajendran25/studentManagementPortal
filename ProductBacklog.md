# Student Management Portal — Product Backlog

## Project Objective
To develop a Student Management Portal that allows administrators to manage student information efficiently.

## Product Backlog

| ID | User Story | Priority | Story Points |
|---|---|---|---:|
| US01 | As an administrator, I want to log in so that I can securely access the portal. | High | 5 |
| US02 | As an administrator, I want to add new student details so that student records can be maintained. | High | 5 |
| US03 | As an administrator, I want to view all students so that I can access student information. | High | 3 |
| US04 | As an administrator, I want to edit student details so that incorrect information can be updated. | High | 3 |
| US05 | As an administrator, I want to delete student records so that outdated records can be removed. | Medium | 3 |
| US06 | As an administrator, I want to search for students by name or ID so that I can find records quickly. | Medium | 3 |
| US07 | As an administrator, I want to view student details such as name, roll number, department, and email. | High | 2 |
| US08 | As an administrator, I want to generate student reports so that I can review student information. | Low | 5 |

## Definition of Done
- The feature works as expected.
- The code is reviewed.
- Basic testing is completed.
- The code is committed and pushed to GitHub.
- The feature is documented.
